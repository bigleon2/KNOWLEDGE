    18→## §1 — SPÉCIFICATION FONCTIONNELLE
    19→
    20→### 1.1 Description
    21→
    22→gen-plan est un skill de **planification de tâches** pour assistant IA. Il fournit un cadre structuré en 4 modes de fonctionnement et 15 étapes (E1-E15) pour analyser, planifier, exécuter, surveiller et adapter toute tâche complexe.
    23→
    24→### 1.2 Les 4 modes
    25→
    26→| Mode | Nom | Description |
    27→|------|-----|-------------|
    28→| M1 | **Planification** | Analyse de la demande, classification, estimation, création du plan d'exécution |
    29→| M2 | **Exécution** | Passage à l'action selon le plan établi, suivi des étapes |
    30→| M3 | **Surveillance** | Monitoring en temps réel de l'avancement, détection d'écarts |
    31→| M4 | **Adaptation** | Ajustement du plan en cas de dérive, recalibration |
    32→
    33→### 1.3 Les 15 étapes (E1-E15)
    34→
    35→| Étape | Nom | Description | Mode par défaut |
    36→|-------|------|-------------|----------------|
    37→| E1 | Analyse de la demande | Décortication de la demande utilisateur, identification des livrables, contraintes et critères de succès | M1 |
    38→| E2 | Inventaire des ressources | Bilan des skills disponibles, outils, fichiers, contexte | M1 |
    39→| E3 | Classification du type de tâche | Routage Type 1 (Document), Type 2 (Visualisation), Type 3 (Web Dev), Type 4 (Data Processing) | M1 |
    40→| E4 | Estimation #token | Calcul budgétaire en tokens de la tâche | M1 |
    41→| E5 | Sélection des skills | Identification des skills pertinents via skills-inventory et KNOWLEDGE.md | M1 |
    42→| E6 | Profilage ressource | Choix du profil NORMAL / ECO / VIEUX PC | M1 |
    43→| E7 | Création du plan | Assemblage du plan structuré avec étapes, dépendances, checkpoints | M1 |
    44→| E8 | Validation du plan | Vérification cohérence, complétude, faisabilité | M1 |
    45→| E9 | Lancement de l'exécution | Démarrage des étapes selon le plan | M2 |
    46→| E10 | Suivi d'étape | Monitoring de chaque étape, log worklog | M2/M3 |
    47→| E11 | Checkpoint intermédiaire | Vérification à mi-parcours, ajustements mineurs | M3 |
    48→| E12 | Détection d'écart | Comparaison réel vs estimé, alertes | M3 |
    49→| E13 | Ajustement | Modification du plan si nécessaire | M4 |
    50→| E14 | Finalisation | Achèvement des étapes restantes | M2 |
    51→| E15 | Bilan et auto-calibration | Retour d'expérience, mise à jour des grilles de calibration, enrichment KNOWLEDGE.md | M1/M4 |
    52→
    53→### 1.4 Classification E3 — Routage des types de tâches
    54→
    55→| Type | Nom | Indicateurs | Action |
    56→|------|-----|-------------|--------|
    57→| Type 1 | Document Creation | Rapport, PPT, DOCX, PDF, XLSX, script, manuscrit | Invoquer skill document (docx/pdf/xlsx/pptx) |
    58→| Type 2 | Data Visualization | Charts, graphes, diagrammes, mind maps, Mermaid | Invoquer skill charts |
    59→| Type 3 | Interactive Web Dev | Pages web, dashboards, apps, Next.js | Invoquer skill fullstack-dev |
    60→| Type 4 | Data Processing | Traitement de données, analyse de fichiers, calculs | Écrire script Python |
    61→
    62→### 1.5 Tagging #token (Norme N1)
    63→
    64→Chaque étape et chaque skill utilisé reçoit un tag `#token` indiquant le coût estimé en tokens. La grille est auto-calibrée après exécutions.
    65→
    66→**Grille de calibration (après 4 exécutions)** :
    67→
    68→| Agent/Skill | #token estimé (par 1000 tokens sortie) |
    69→|-------------|---------------------------------------|
    70→| Planification (E1-E8) | 1500-3000 |
    71→| Exécution simple | 2000-5000 |
    72→| Exécution complexe | 5000-15000 |
    73→| Surveillance (E10-E12) | 500-1500 |
    74→| Auto-calibration (E15) | 800-2000 |
    75→
    76→### 1.6 Snippets (Norme N2)
    77→
    78→gen-plan peut générer des snippets de code réutilisables pendant l'exécution. Chaque snippet est tagué et versionné.
    79→
    80→### 1.7 Python uniquement (Norme N3)
    81→
    82→**Règle #7** : Tous les scripts générés par gen-plan doivent être en Python. Aucun script shell (bash, sh, powershell). Cette règle garantit la portabilité cross-platform.

    87→
    88→### 2.1 Stack technique
    89→
    90→- **Langage** : Python (scripts), Markdown (documentation), YAML (frontmatter)
    91→- **Environnement** : `my-project/skills/gen-plan/`
    92→- **Pas de dépendance externe** (sauf intégration KB optionnelle)
    93→
    94→### 2.2 Structure des fichiers
    95→
    96→```
    97→skills/gen-plan/
    98→├── SKILL.md                          # Skill principal (8.5 Ko)
    99→├── references/
   100→│   ├── etapes-detaillees.md          # Détail des 15 étapes
   101→│   ├── grille-token.md               # Grille de calibration #token
   102→│   ├── classification-types.md       # Routage Type 1-4
   103→│   └── profils-ressource.md          # NORMAL / ECO / VIEUX PC
   104→└── evals/
   105→    └── evals.json                    # Cas de test d'évaluation
   106→```
   107→
   108→### 2.3 Auto-calibration E15
   109→
   110→Mécanisme d'auto-calibration à l'étape E15 :
   111→
   112→| Écart estimé vs réel | Action |
   113→|----------------------|--------|
   114→| 0-20% | Aucune action (estimation fiable) |
   115→| 20-35% | Ajustement de la grille (paramétrage fin) |
   116→| >35% | Recalibration complète (révision des coefficients) |
   117→
   118→La calibration porte sur :
   119→- La grille #token par agent/skill
   120→- Les seuils de profil ressource
   121→- Les ratios de complexité par type de tâche
   122→
   123→### 2.4 Profils ressource (3 profils)
   124→
   125→| Profil | Contexte | Règles |
   126→|--------|----------|--------|
   127→| **NORMAL** | Ressources standards | Aucune restriction, utilisation de tous les skills |
   128→| **ECO** | Discussion courte (< 5 sessions) | Réduction des étapes de surveillance, snippets simplifiés |
   129→| **VIEUX PC** | Environnement limité | Scripts légers, pas de graphiques lourds, profil ECO renforcé |
   130→
   131→### 2.5 Intégration KB (gen-plan >= v3.3.0)
   132→
   133→Depuis v3.3.0, gen-plan intègre un **Registre KB** (Knowledge Base) :
   134→
   135→- **`kb_path`** : chemin vers `skills/KNOWLEDGE.md`
   136→- **`--kb-skill`** : flag pour activer la consultation KB
   137→- **Protocole de Découverte** : scan du registre pour identifier les skills pertinents
   138→- **Matrice de décision** : agent × skill (statique + dynamique via KB)

   357→## §8 — NOTES DE CONCEPTION
   358→
   359→### 8.1 Pourquoi 15 étapes ?
   360→
   361→Les 15 étapes couvrent le cycle de vie complet d'une tâche complexe : de l'analyse initiale (E1) au bilan post-exécution (E15). Chaque étape a un objectif clair, des inputs/outputs définis, et des critères de validation.
   362→
   363→### 8.2 Pourquoi 3 profils ?
   364→
   365→Les profils NORMAL/ECO/VIEUX PC permettent d'adapter la planification aux contraintes matérielles. Le profil ECO est conçu pour les discussions courtes, le profil VIEUX PC pour les environnements limités.
   366→
   367→### 8.3 Pourquoi auto-calibration ?
   368→
   369→L'estimation en tokens est intrinsèquement imprécise. L'auto-calibration E15 permet d'améliorer continuellement les estimations en comparant le prévu au réel, avec des seuils d'action clairs (20-35% ajustement, >35% recalibration).
   370→
   371→### 8.4 Pourquoi Python uniquement ?
   372→
   373→La règle N3 (Python uniquement) garantit la portabilité cross-platform. Les scripts shell sont dépendants du système d'exploitation, tandis que Python est universellement disponible dans l'environnement.

   760→## Type 1 — Document Creation

   770→- Tableur → `xlsx`
   771→- Présentation → `pptx`
   772→- Markdown seul → aucun skill (rédaction directe)

   775→- "Écris un rapport d'analyse" → Type 1, skill docx

   778→
   779→**Contre-exemples** :
